# Журнал ошибок Bressoles

При обычном запуске `python Main.py` журнал включается автоматически **до импорта
Pygame и игровых модулей**. Устанавливать зависимости не нужно.

## Где найти

В Windows нажмите **Win+R**, вставьте `%LOCALAPPDATA%\Bressoles\Logs` и нажмите Enter.
Или выполните `python open_logs.py` из папки игры. Скрипт откроет папку журналов.
Если основная папка недоступна для записи, используется `%TEMP%\Bressoles\Logs`;
скрипт покажет и её. Если обе папки недоступны, игра продолжит запуск без журнала
и выведет предупреждение в консоль.

Каждый запуск — отдельная папка `session-ДАТА-ВРЕМЯ-PID` (в имени время UTC).
Хранятся **10 последних запусков приложения**, а не 10 раундов. При следующем
запуске старые папки удаляются. Скопируйте нужную папку до дальнейших экспериментов.

- `game.log` — последние события, сообщения консоли и traceback ошибок Python.
  `game.log.1` и `game.log.2` — более ранние части того же запуска; читать в порядке
  `.2`, `.1`, основной файл. Каждая часть ограничена примерно 2 МБ.
- `native-crash.log` — отдельный вывод Python faulthandler при поддерживаемых
  низкоуровневых сбоях, включая некоторые сбои SDL/Pygame. Пустой файл нормален.
- `status.json` — результат запуска: `completed` — штатное завершение;
  `crashed` — необработанная ошибка основного потока; `completed_with_errors` —
  завершение после ошибки фонового потока; `failed_exit` — ненулевой код выхода;
  `incomplete` — выход до штатного завершения.

`running` / `running_with_errors` означает, что процесс ещё работает **или был
оборван без возможности записать результат**. Если игра уже закрыта, такой статус
помогает обнаружить прерванный запуск, но сам по себе не доказывает причину краша.

## Что делать после вылета

Найдите папку по времени сбоя, скопируйте или заархивируйте **всю папку запуска**
и передайте её для разбора. Полезно также указать последнее действие перед вылетом.
Повторный запуск не перезаписывает предыдущий журнал.

Записываются версия Python, ОС, Pygame и SDL, Git commit (если доступен), параметры
экрана, этапы загрузки, создание и смена экранов, начало партии и обработка ходов
(уровень, босс, день, деньги, цены, акции, карты на столе). Существующие сообщения
`print` и stderr также сохраняются. Каждая строка сбрасывается из буфера в файл;
на диск не пишется каждый кадр. Исключения содержат стек с файлами и номерами строк.

Журналы локальные: автоматической отправки нет. Они могут содержать локальные пути
и диагностические сообщения игры. Это не запись всех действий и не воспроизведение
партии. Отключение питания, принудительное убийство процесса или некоторые сбои
драйвера могут оставить только последние события без точной причины; гарантии
сохранности при отказе диска/питания нет. Нативный журнал — стек Python, не полный
дамп памяти Windows. Ошибки до начала исполнения Main.py также не перехватываются.

При импорте `Main` тестами журнал автоматически не включается. Для собственного
лаунчера вызывайте `start_session()` до импорта игры и `finish_session()` только
при штатном завершении.
