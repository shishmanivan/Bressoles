# Сохранения и восстановление профилей

Для каждого слота используются файлы в папке `Profiles`:

- `profile_N.json` — основной профиль, включая прогресс и текущую партию.
- `profile_N.json.bak` — резервная копия предыдущего сохранения. При первом
  сохранении основной файл и копия содержат одинаковые данные.
- `profile_N.json.corrupt-*.bak` — исходные байты повреждённого файла,
  сохранённые перед автоматическим восстановлением. Эти файлы не удаляются
  и не перезаписываются автоматически.

Копия создаётся перед атомарной заменой основного файла. Если записать копию
не удалось, основной файл не заменяется. При ошибке замены основного файла
предыдущее сохранение остаётся доступным.

При загрузке проверяются JSON и основные структуры профиля. Если основной
файл повреждён, игра проверяет резервную копию. Перед восстановлением оригинал
сохраняется отдельно. При отсутствии основного файла исправная копия также
восстанавливается автоматически. Ошибка доступа к основному файлу не считается
повреждением и не запускает его замену.

После восстановления экран профилей сообщает, что использована резервная
копия: последняя запись могла быть потеряна. Если исправной копии нет,
проблемный слот помечается как недоступный. Его нельзя переименовать,
выбрать или перезаписать обычными операциями сохранения; можно выбрать
другой слот. Исходные файлы остаются для дальнейшего восстановления.

Отсутствие обоих файлов означает новый профиль. Повреждённый файл не считается
новым профилем. Старые сохранения с отсутствующими необязательными полями
поддерживаются; миграции выполняются и после восстановления резервной копии.

Для существующих профилей резервные копии начинают создаваться при следующем
сохранении. Эта защита не восстанавливает данные, которые уже были утрачены
до появления исправной копии, и не защищает от потери всего диска.

Проверки: `tests/test_profile_recovery.py`, `tests/test_profile_contract.py`
и сценарии запуска с повреждённым профилем в `tests/test_main_flow.py`.
